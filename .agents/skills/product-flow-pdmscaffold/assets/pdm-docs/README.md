# PdM Documents

このディレクトリは、プロダクト判断の正本と、その判断に使う資料を置く場所です。

各ファイルは雛形です。固有の市場、顧客、事業モデル、機能、技術を前提にせず、見出しと「どの深さまで書くか」だけを示します。

## 構成

| Path | 役割 |
| --- | --- |
| [`STRATEGY.md`](./STRATEGY.md) | 誰に、どの問題を、どう勝ち、どう成立させるか |
| [`PRODUCT_PLAN.md`](./PRODUCT_PLAN.md) | 何を、どの順番で、どこまで作るか |
| [`CURRENT_PRODUCT.md`](./CURRENT_PRODUCT.md) | 現在できることと、その確認根拠 |
| [`PRODUCT_GAP_ANALYSIS.md`](./PRODUCT_GAP_ANALYSIS.md) | 目標と現状の差分、優先順位、解消条件 |
| [`personas/`](./personas/) | 利用者像と利用文脈 |
| [`references/`](./references/) | 調査、観察、計算、出典など判断の材料 |

実装設計、ADR、API、移行計画、テスト・リリース証跡は、必要になった時点で `docs/engineering/` など別の正本へ分けます。

## 配置ルール

1. `docs/pdm/` 直下には上記の正本だけを置く
2. 直下の正本は大文字英語・日付なしにする
3. ペルソナは `personas/{CC}-{scope}-{descriptive-role}.md` とする
4. 参照資料は小文字ケバブケースとし、時点が重要なら `-YYYY-MM-DD` を付ける
5. 新規ファイルを増やす前に、既存正本へ吸収できないか確認する
6. 調査の全文を正本へ複製せず、判断と要約だけを正本へ反映する

## 書き分け

| ラベル | 用途 | 最低限必要な情報 |
| --- | --- | --- |
| 事実 | 観察・計測・実装・一次情報で確認済み | 根拠、確認日 |
| 決定 | 採用した方針 | Owner、決定日、理由 |
| 仮説 | まだ検証していない見立て | 検証方法、判定条件 |
| 未決定 | 判断が必要な論点 | Owner、次の行動 |

事実、決定、仮説を同じ文章の中で曖昧に混ぜないようにします。

## 記述の深さ

- 各大見出しでは、結論または状態を最初に1〜3文で書く
- 表は比較、対応、優先順位を示すときだけ使う
- 一つの節で複数の独立した論点を扱わない
- 正本は判断に必要な深さに留め、調査ログや技術詳細は別ファイルへ分ける
- 未記入の節は削除せず、`未決定` または `該当なし` と理由を書く
- テンプレート内のコメントは記入後に削除する

## 更新順序

```text
personas/ + references/
          -> STRATEGY.md
          -> PRODUCT_PLAN.md
          -> CURRENT_PRODUCT.md
          -> PRODUCT_GAP_ANALYSIS.md
```

- 戦略が変わったら、計画と Gap への影響を確認する
- 要求が変わったら、現状と Gap を再確認する
- 実装が変わったら、現状を先に更新してから Gap を更新する
- 調査結果は参照資料に残し、採用した判断だけを正本へ反映する

## 更新時の確認

- 相互リンクが切れていない
- 古い用語、旧ファイル名、失効した判断が残っていない
- 外部情報に確認日がある
- 優先項目に Owner と解消条件がある
- `未決定` が決定済みのように読めない
- 同じ内容を複数の正本で重複管理していない

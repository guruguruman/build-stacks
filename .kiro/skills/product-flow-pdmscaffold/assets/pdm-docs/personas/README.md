# Personas

ペルソナは、属性の物語を作るためではなく、特定の利用状況・行動・目的・制約を共有するために使います。

## ファイル名

`{CC}-{scope}-{descriptive-role}.md`

例: `JP-end-user-small-team-operator.md`

## 構成テンプレート

```markdown
# [Descriptive Persona Name]

## 0. 文書状態
<!-- 仮説 / 調査中 / 検証済み、Owner、最終更新、根拠を書く。 -->

## 1. 利用文脈
<!-- 問題が起きる環境、頻度、関係者、現在の道具を書く。 -->

## 2. Goals / Jobs
<!-- 機能ではなく、達成したい進歩や成果を書く。 -->

## 3. 現在の行動
<!-- 時系列またはJobの段階ごとに、行動・道具・摩擦を書く。 -->

## 4. 問題と制約
<!-- 頻度、強度、回避策、導入障壁を分ける。 -->

## 5. 代表シナリオ
<!-- 2〜5件。Trigger、行動、期待結果、失敗時の影響を書く。 -->

## 6. 成功条件
<!-- 観察・計測できる形で書く。 -->

## 7. 検証すべき仮説
<!-- 仮説、方法、判定条件、状態を書く。 -->

## 8. 設計への示唆
<!-- 確認済み事実と推定を分ける。具体画面を先に固定しない。 -->

## 9. 参照資料
<!-- interview/research/source へのリンクを書く。 -->
```

## 注意

- 年齢、性別、職業などは判断に影響する場合だけ記載する
- 一人の架空人物の好みを市場全体へ一般化しない
- 調査前の内容は必ず仮説と明記する
- Primary / Secondary の優先順位は `STRATEGY.md` と一致させる
- ペルソナごとに別プロダクトを作るような要求分岐を安易に増やさない
